# 探针题库 —— 「全新 AI 实测」的标准任务

**用途**：定期（或每次大改后）把下面任意一题丢给一个**全新 context 的 AI**，
只允许它读本仓文件，然后看它**卡在哪**。

**为什么有效**：本仓实测证过 —— 自查会漏，实测会找到。四轮实测产出 7 个修复提交，
其中包括**最深的三类问题**：
  · 文档在为不存在的事实背书（声称有 `DNS_KEYS` 判据，代码里从来没有）
  · 闸门静默消失（3 道 DNS 审计因路径模板过时被 `continue` 吞掉）
  · 文档自相矛盾（说「改版本号要改脚本」，而脚本里没有版本串）

**为什么不能自动化**：它验证的是「文档对**读者**是否够用」——
只有真读者（一个新 AI）能给出答案。静态检查查不出「读者会不会卡住」。

---

## 用法

```text
你是第一次接触 <仓库路径> 的 AI 编码助手。
只依靠仓库里的文件回答下面的问题（不要用先验知识填空）。

<从下面题库挑 3-5 题>

严格要求：
1. 每题必须指出「从哪个文件读到的」（路径 + 大概位置）
2. **必须如实报告卡住的地方** —— 本测试目的是找缺口，不是证明文档好
3. 不要修改仓库任何文件（只读）
4. ⚠️ 每题读 1-2 个文件就够，**不要通读仓库**；限时 10 分钟

输出：每题给 ①答案 ②依据 ③有无卡住。最后给「最大的 1-2 个问题」。
```

⚠️ **限时是必须的**：实测有 agent 通读 30 分钟超时。
限时能同时检验「能否快速定位」（那正是 AI 效率的核心指标）。

## 判读结果

| 现象 | 含义 | 处置 |
|:--|:--|:--|
| agent **读错文件**（改了生成物）| 入口表不够明确 | 补根 `AGENTS.md` 的「改动去哪」表 |
| agent **找不到入口** | 入口缺失或被屏蔽 | 查 `check_ai_entry.py` 的判据是否该收紧 |
| agent **说「文档没写」** | 真缺口 | 补 SOP（像第 2 题的规则集步骤）|
| agent **引用了不存在的节/文件** | 文档造假或引用过时 | 那是**最严重的一类** → 补 `check_dead_refs.py` / `check_section_refs.py` |
| agent **超时** | 文档总量对通读偏大 | 检查是否该拆；但**先确认它有没有按「按需 grep」的指引做** |
| agent **答对但靠猜** | 文档没给判据 | 补明确依据 |

⚠️ **发现缺口后要做两件事**（只做第一件不够）：
1. 修那一处
2. **加判据或把它加进本文件** —— 否则同类问题会再出现

| 3 | 验证 + 找新问题 | 超时；但日志线索导出 3 批修复（静默跳过 / 已删引用 / 旧文件名）|
| 4 | 限时 3 题 | 3 题全对 ✓（前几轮修复起效），另暴露 1 处数字错 |
